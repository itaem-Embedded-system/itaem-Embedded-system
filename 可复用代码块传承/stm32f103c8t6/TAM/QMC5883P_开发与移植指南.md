# QMC5883P 开发与移植使用指南

本指南整合了 **驱动移植说明**、**业务层开发规范** 及 **调试模块 (VOFA+) 使用手册**，旨在帮助开发者快速上手 QMC5883P 地磁传感器的开发与调试。

---

# 第一部分：驱动移植与开发指南

## 1. 架构概览

本驱动采用 **三层架构** 设计，以实现最大程度的可移植性和模块化：

| 层级 | 目录 | 定位 | 职责 | 依赖 |
| :--- | :--- | :--- | :--- | :--- |
| **Device** | `device/` | **纯逻辑驱动** | 寄存器协议、状态机、数据转换 (Raw -> Gauss) | 仅依赖标准 C (`stdint.h`)，**硬件无关** |
| **Platform** | `platfrom/` | **硬件适配层** | 实现 I2C 读写、延时函数、平台初始化包装 | 依赖 MCU SDK (如 STM32 HAL) |
| **App** | `app/` | **业务逻辑层** | 传感器生命周期管理 (初始化、轮询、容错、诊断) | 依赖 Platform 层 |
| **Core** | `Core/` | **板级初始化层** | I2C/UART/GPIO 时钟与引脚初始化 | 由 CubeMX 生成，供 Platform/App 调用 |

说明：当前工程目录名为 `platfrom/`（历史命名），文档与代码均按该实际目录名使用。

---

## 2. 移植步骤 (Porting Guide)

### 2.1 文件准备
将 `device` 和 `platfrom` 文件夹复制到你的工程目录中，并确保构建系统已包含对应 `.c/.h` 文件。

### 2.2 适配 Platform 层
打开 `platfrom/QMC5883P_platform.c`，修改以下接口以适配你的硬件：

1.  **`qmc_platform_write`**: 替换为你的 I2C 写函数 (如 `HAL_I2C_Mem_Write`)。
2.  **`qmc_platform_read`**: 替换为你的 I2C 读函数 (如 `HAL_I2C_Mem_Read`)。
3.  **`qmc_platform_delay`**: 实现毫秒级延时 (如 `HAL_Delay` 或 RTOS `osDelay`)。

### 2.3 初始化 (App 层)
在你的应用代码中进行初始化：

```c
stmdev_ctx_t ctx;

// 1. 绑定硬件句柄 (以 STM32 HAL 为例)
qmc5883p_platfrom_init_ctx(&ctx, &hi2c1);

// 2. 执行标准初始化 (复位 + 校验 ID + 设置连续模式)
if (qmc5883p_platfrom_init_device(&ctx) != 0) {
    // 处理初始化失败 (如亮红灯)
}
```

### 2.4 接口契约表（输入/输出/错误/重试建议）

下表基于当前工程实现（`platfrom/QMC5883P_platfrom.h` 与 `platfrom/QMC5883P_platform.c`）整理。

| 接口 | 输入 | 输出 | 错误返回 | 当前实现行为 | 重试建议 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `qmc5883p_platfrom_init_ctx` | `ctx`、`i2c_handle` 非空 | 无返回值 | 无（空指针时直接返回） | 绑定 `read_reg/write_reg/mdelay/handle` | 上层调用前确保句柄已由 `MX_I2C1_Init()` 初始化 |
| `qmc5883p_platfrom_init_device` | 已绑定的 `ctx` | `0` 成功 | `-1` 失败 | 读 ID、写默认配置，并回读 `CTRL1/CTRL2` 校验 | 建议在 App 层按固定节拍重试（如 1s），并输出诊断状态 |
| `qmc5883p_platfrom_poll_raw` | `ctx`、`mag[3]`、`has_new_data` | `mag` 与 `has_new_data` | `-1` I2C 错误 | 先查 DRDY；DRDY 异常时做一次 fallback 直读 | 建议在 App 层做连续错误计数，超过阈值触发重新初始化 |
| `qmc5883p_platfrom_delay_ms` | `ctx`、`ms` | 无 | 无 | 优先走 `ctx->mdelay`，否则回退 `HAL_Delay` | RTOS 场景建议替换为非阻塞延时实现 |

I2C 底层读写默认带重试：`QMC5883P_I2C_RETRY_MAX = 3`，每次失败间隔 `2ms`。

## 3. 业务开发最佳实践 (Best Practices)

建议参考 `app/TAM.c` 的实现模式：

### 3.1 非阻塞轮询
不要在主循环中使用 `HAL_Delay`，建议使用时间戳差值法：
```c
if ((HAL_GetTick() - last_tick) >= 100) { // 10Hz
    last_tick = HAL_GetTick();
    // 执行轮询...
}
```

### 3.2 自动容错 (Watchdog 机制)
传感器可能会因震动或干扰掉线，**必须**实现自动恢复机制：
1.  **通信错误计数**：如果连续 N 次 I2C 读取失败，触发重置。
2.  **数据异常检查**：如果数据全为 0 (常见死机现象) 或超出物理量程，触发重置。
3.  **重置流程**：调用 `qmc5883p_init_set` 重新写入配置寄存器。

# 第二部分：VOFA+ JustFloat 调试模块使用说明

## 1. 功能简介
本模块用于将 QMC5883P 采集到的 **原始数据 (Raw)** 和 **高斯换算值 (Gauss)**，通过串口 (UART2) 以 **JustFloat** 协议实时发送至电脑，配合 **VOFA+** 软件进行波形显示。

> **适用场景**：快速验证数据、观察噪声、标定辅助。

### 2.2 VOFA+ 软件设置

按当前工程参数设置：

1. 协议/数据引擎：`JustFloat`
2. 串口：选择你的 USB-TTL 端口（如 `COM8`）
3. 波特率：`115200`
4. 数据位：`8`
5. 校验位：`None`
6. 停止位：`1`
7. 流控：`None`
8. 通道数：`7`（CH0~CH6）
9. 采样节拍：约 `100ms/帧`（10Hz）

连通性快速检查：

1. 若 CH6(`tick`) 连续增长，说明串口与 JustFloat 解包正常。
2. 若 CH6 不增长，先排查串口参数、连线、以及 `USART2` 是否被占用。


## 3. 数据通道定义 (100ms/帧)

| 通道 | 变量名 | 含义 | 单位 |
| :--- | :--- | :--- | :--- |
| **CH0** | `mag_x_raw` | X轴原始值 | LSB |
| **CH1** | `mag_y_raw` | Y轴原始值 | LSB |
| **CH2** | `mag_z_raw` | Z轴原始值 | LSB |
| **CH3** | `mag_x_gauss` | X轴磁场（由 `mag_x_raw / 3750` 换算） | Gauss |
| **CH4** | `mag_y_gauss` | Y轴磁场（由 `mag_y_raw / 3750` 换算） | Gauss |
| **CH5** | `mag_z_gauss` | Z轴磁场（由 `mag_z_raw / 3750` 换算） | Gauss |
| **CH6** | `tick` | 调试时间基准，用于观察采样节拍与数据刷新连续性 | ms |

说明：

- CH0~CH2 与 CH3~CH5 表达的是同一组三轴磁场数据，差别仅在单位：前者是原始计数值，后者是换算后的物理量。
- CH6 仅用于调试链路观测，不参与磁场计算。

## 4. 注意事项 (Known Issues)

*   **资源竞争**：当前工程中，`TAM_Loop` (业务) 和 `Main_VofaLoop` (调试) 都会轮询 I2C。在极少数情况下可能冲突。
*   **建议**：本调试模块仅供开发阶段使用，正式产品中请移除 `Main_VofaLoop`，统一由 `TAM` 模块采集数据。
